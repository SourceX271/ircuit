# Ircuit 实施计划

> 需求基线见 [需求文档.md](./需求文档.md)。本文件定义工程结构、里程碑验收标准、技术决策与风险对策。

---

## 1. 验收基线

一个 Ircuit 版本算「合格」，必须同时满足：

1. 三平台（Windows / macOS / Linux）能构建、能启动、能连接、能对话。
2. 协议层有单测，`cargo test` 与 `cargo clippy -- -D warnings` 全绿。
3. 前端 `tsc --noEmit` 与 `vitest` 全绿。
4. 关键流程纯键盘可完成。
5. 无遥测、无隐式外联；凭据不出现在明文文件中。


### M1 — 协议内核
**目标**：真的能连上 IRC 并收发消息。

**已确认决策**
- 界面做到**可用的连接表单 + 服务 buffer**：用户能亲自走完「建网络 → 连接 → 入频道 → 对话」全流程。
- 验证方式：仓库内**内置 mock IRC 服务器**做自动化回归（CAP / SASL / 重连 / 分片可控可重现），同时保留连真实网络的手动验证。
- SASL 只做 **PLAIN + EXTERNAL**；SCRAM-SHA-256 需要 HMAC/PBKDF2 与多轮协商，放到 M4 与客户端证书一起做。

**交付**
- `ircuit-proto`：消息解析/序列化、IRCv3 tag 转义、mIRC 格式码编解码、消息分片、RFC 样例单测
- `ircuit-client`：tokio + rustls 连接、DNS、连接状态机、CAP LS 协商、SASL PLAIN/EXTERNAL、PING/PONG 保活、指数退避重连、事件总线
- `ircuit-testserver`：进程内 mock IRC 服务器，供集成测试与手动联调
- 可用 UI：网络配置表单 → 连接 → 加入频道 → 收发消息，服务 buffer 展示原始流量

**验收**：集成测试对着 mock 服务器跑通注册 / 入频道 / 收发 / 重连；连上 Libera.Chat 并能真实对话；断网后自动恢复；解析层单测覆盖边界样例。

### M2 — 会话 UI
**目标**：日常可用的完整界面。

**状态**：**已完成**。交付项与验收见 §9「M2 验收」。

**已确认决策**
- mIRC 颜色**映射到主题自适应色**，而不是照搬调色板：深色主题下原始的「白底黑字」与纯红纯绿既刺眼又对比度不足。要保留的是「有人在这里用了颜色」这一信息，不是具体色值。
- 成员列表做**成员 + 权限前缀 + away + 右键菜单**（WHOIS / 私聊 / OP / Voice / Kick / Ban / 忽略）；频道模式面板与 ban 列表编辑留到 M3。
- 通知只做**应用内**（高亮规则、未读计数、标签提示）；桌面通知、托盘、声音放 M8，避开三平台的权限与适配问题。

**交付**
- 三栏布局、两侧可收起
- 频道状态模型：成员、权限前缀、away、topic、channel modes，由 NAMES/JOIN/PART/QUIT/KICK/NICK/MODE/TOPIC/005 驱动
- 网络/频道树（未读、高亮、排序、折叠）、标签栏
- 消息流虚拟列表：日期分隔、连续分组、mIRC 格式码与颜色、链接、自己/他人/系统消息区分、首字母头像
- 成员列表：排序、前缀、away、右键菜单
- 输入区：多行、Enter/Shift+Enter 可配、Tab 补全、完整 `/` 命令集、历史、按 buffer 草稿
- 命令面板（Ctrl+K）、快捷键系统
- 应用内通知与关键词高亮规则

**验收**：3 网络 + 10 频道日常使用流畅；纯键盘完成全部核心操作。

## 4. 关键技术决策

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| IRC 协议实现 | 自研（不依赖第三方 IRC crate） | 需要 IRCv3 全量、DCC、编码、Bouncer 精细控制 |
| IPC 契约 | tauri-specta 自动生成 TS 类型 | 避免前后端类型漂移 |
| 前端持有 socket | 否 | 协议逻辑集中在 Rust，UI 可替换、可测试 |
| 插件沙箱 | QuickJS (rquickjs) | 体积小、无 IO 权限、易设资源上限 |
| 编码检测优先级 | 手动设置 > 自动检测 | 检测会误判，用户必须能覆盖 |
| 凭据存储 | OS Keyring（非 SQLite） | 系统级加密，配置文件可安全备份 |
| 消息存储 | SQLite + FTS5 | 单文件、事务安全、全文检索开箱可用 |
| 长列表 | 虚拟滚动 + 分页加载 | 内存与帧率可控 |
| 事件传输 | 增量事件 + 环形缓冲 | 长会话不膨胀 |
| IPC 整数 | 跨 IPC 只用 32 位及以下整数 | specta 拒绝导出 `u64`/`i64` 等，见第 7 节 |
| 测试进程模型 | vitest `pool: 'threads'` | 不依赖派生子进程，容器与受限环境更稳，也更快 |

## 7. IPC 整数约定

Rust 与前端之间传整数时，**只用 32 位及以下类型**（`u8` / `i8` / `u16` / `i16` / `u32` / `i32`）。

原因：生成的 TypeScript 里整数是 JS 的 `number`（IEEE-754 双精度），只能无损表示到 2^53。
因此 `specta` 会**直接拒绝导出** `u64`、`i64`、`usize`、`isize`、`u128`、`i128`，
在编译期就报错，而不是等到线上出现精度问题。

确实需要 64 位语义时，按以下优先级处理：

1. **换更小的单位（首选）**。例如运行时长用秒而不是毫秒 —— `u32` 秒可以表示 136 年。
2. **需要绝对无损的大整数**（例如消息 ID）时用 `String` 传递，配合
   `#[specta(type = String)]` 与 serde。
3. **万不得已**才用 `#[specta(type = specta_typescript::Number)]` 显式放弃精度保护，
   并且**必须**在注释里写清为什么在这里是安全的。

## 8. 受限环境开发说明

本项目在文件与进程受限的环境（容器、CI 沙箱、受管终端）里同样可以开发，
依赖三处本机配置，均不入库。

| 问题 | 现象 | 对策 |
| --- | --- | --- |
| 缓存目录不可写 | cargo / npm 无法写 `~/.cargo`、`%LOCALAPPDATA%` | 缓存重定向到项目内 `.cache/`：cargo 用 `CARGO_HOME`，npm 用项目 `.npmrc` |
| cargo TLS 握手失败 | `schannel: AcquireCredentialsHandle failed` | `scripts/dev/cargo-proxy.mjs` 提供本机明文 HTTP registry，TLS 交给 Node |
| 禁止带管道的子进程 | Vite 探测 `net use` 时 `spawn EPERM`，vitest 起 worker 失败 | `scripts/dev/sandbox-shim.mjs` 预加载垫片；vitest 使用线程池 |
| 界面无法目视验证 | 窗口被遮挡时普通截屏只能拿到桌面像素 | `scripts/dev/capture-window.ps1` 用 PrintWindow 直接渲染窗口内容 |

注意：`scripts/dev/*.ps1` 必须保持 **ASCII-only**。Windows PowerShell 会把无 BOM 的脚本
按 ANSI 解码，中文会破坏解析。

具体命令见 README 的「受限环境」一节。

## 9. 落地记录

跨里程碑的设计决定，后续改动必须遵守。

### M0–M1

| 决定 | 原因 |
| --- | --- |
| **事件回放按 `seq` 交错应用** | Tauri 事件不做缓冲，挂载前发出的事件不会重放。后端为每个网络保留有界回放（消息 500 条、原始流量 1000 条），每条事件带单调递增 `seq`；前端先订阅、再取回放，靠 `seq` 去重。回放**必须把两类事件按 `seq` 合并排序后统一应用** —— 它们共用一个计数器，先应用其中一类会把高水位推过另一类，导致整类事件被静默丢弃。 |
| **IPC 绑定只由专用 bin 生成** | `run()` 曾在 debug 下顺带导出绑定，于是运行一个陈旧的二进制会把新绑定覆盖回旧版本；前端随后调用不存在的命令而整棵树崩溃，症状（窗口全白）与原因毫无关联。现在只有 `pnpm cargo:bindings` 会写这个文件。 |
| **TLS 提供者用 ring，不用 aws-lc-rs** | 后者在 Windows 上需要额外安装 NASM 才能编译汇编优化，等于给三平台构建多加一个工具链依赖。 |
| **`ircuit-testserver` 用字符串匹配，不复用 `ircuit-proto`** | 与被测代码共享解析器，就无法发现解析器自身的缺陷。mock 必须是一个独立的见证者。 |
| **原始行输出剥离 CR/LF** | 参数里的换行能让对端（或插件）注入新命令，这是 IRC 客户端的经典漏洞；协议没有转义机制，只能剥离。 |
| **昵称字符集按 RFC 1459** | `[ ] \ ^ { } \|` 与反引号都是合法昵称字符，因此 `[me]` 是一个整体 token，不被视为提及。 |

### M2

| 决定 | 原因 |
| --- | --- |
| **命令表是唯一事实来源** | 命令的元数据（名称、别名、用法、说明）与解析行为写在同一个 `COMMANDS` 表里：解析器、Tab 补全候选与 `/help` 都从它派生。分成「一个 switch + 一段手写帮助字符串」的话，加命令的人必然只改其中一处。 |
| **命令补全候选里主名排在别名前** | 否则 `/qu` 会先补成 `/query`（`/msg` 的别名）而不是 `/quit`。 |
| **补全会话以「写入的文本区间 + 光标位置」为身份** | 用「当前词」判断是否继续循环，在首次 Tab 扩展公共前缀后就会失配（词变了）；只看区间内容则会在用户接着输入时错误地继续循环。两者都要满足才算同一次补全。 |
| **昵称补全在行首才补 `: `** | 行首补全昵称的目的就是「称呼某人」；句中补全只是插入一个词，加冒号会把句子写坏。 |
| **补全频道参数时无 `#` 也能匹配** | `/join rust` 是所有人打字的方式；匹配时同时比对 `rust` 与 `#rust`，但替换结果一定带 `#`，因为有线格式需要它。 |
| **首字母 Tab 只补到公共前缀，不补冒号** | 公共前缀是片段而不是一个完整的昵称，按昵称规则加 `: ` 会得到 `alic: `。 |
| **`/set` 只能改输入框相关选项，`/help` 只输出到输入框上方** | M2-9 的命令面板才是通用设置入口；这里保持最小，避免两个入口各自演化。 |
| **草稿、历史、最后发言人放在 composer 自己的 store 里** | 它们既不是后端状态也不该被当作会话数据持久化（M3 才落地）。放在 `session` store 里会让人误以为它们和消息同源。 |
| **模式操作只保留一条 IPC 通路 `set_mode`** | `op` / `voice` / `ban` 只差模式字母与参数，具体动作在前端拼装（`setMemberMode` / `banUser`）。每加一个权限动作不必改 Rust。 |
| **`TOPIC` 用 `Option<String>` 区分查询与清除** | `TOPIC #c`（查询）、`TOPIC #c :text`（设置）、`TOPIC #c :`（清除）是三个不同的请求；用 `None`/`Some("")` 保留这个区别，而不是让 `undefined` 兼表其一。 |
| **mock 服务器的观测状态无条件同步** | 原先「非空才同步」的写法让 `PART`、清除 topic、`AWAY` 复位永远传不到观测端——mock 自己藏起了被测行为。测试直接暴露了这个缺陷。 |
| **单字尾参数不带冒号** | `AWAY lunch`、`KICK #c bob spamming` 与 `AWAY :lunch` 在协议上等价，`to_wire` 取最简形式；含空格或空串时才补冒号。断言这类线格式时不要写死冒号。 |
| **可用性验证优先用 jsdom 组件测试** | 本机受限环境无法启动 GUI 截图（沙箱拒绝了提权）。组件测试能覆盖权限判定、禁用态与命令参数，比截图更严谨；纯视觉问题暂时只能靠代码审查。 |
| **快捷键也是一张表** | 派发、命令面板、将来的帮助面板都从 `SHORTCUTS` 读。表里同时决定了按键怎么写（`Ctrl+K` / `⌘K`），避免同一个组合在两处各写一遍字符串。测试还断言「没有两个快捷键占用同一组合」——重复绑定意味着一方永远不会触发。 |
| **修饰键严格匹配** | `Ctrl+Shift+K` 不得同时触发 `Ctrl+K`，否则两个快捷键都变得不可靠。`mod` 按平台解析为 Ctrl 或 Command，其余修饰键必须双向精确相等。 |
| **面板打开时吞掉其它快捷键** | 面板自己处理方向键与回车；此时执行 `Ctrl+W` 会作用于用户看不见的缓冲区。只有「开关面板」这一个快捷键例外。 |
| **指针事件用 `mousedown` 而非 `click`** | 面板输入框失焦会先关掉面板，`click` 就再也到不了。同时 `onMouseDown` 里 `preventDefault` 把焦点留在输入框。 |
| **缓冲区排序抽成 `orderedBuffers`** | 侧栏显示顺序与「下一个/上一个会话」必须一致；各写一份的话，快捷键迟早会跳到不是下一行的位置。 |
| **`digits` 属于快捷键而不是按键组合** | 「跳到第 N 个会话」是一条语义，写成 9 行只会让表和面板都变吵；匹配时由所属快捷键提供该标志，避免两处各写一份而互相矛盾。 |
| **草稿即输入框的值** | 原先输入框另存一份本地 state，导致切换 buffer 时要用 effect 同步，而那个 effect 与任何外部写入（命令面板插入命令）都是竞态。改成直接从 store 派生后，同步逻辑与竞态一起消失。 |
| **面板插入命令而不是执行命令** | 大多数命令需要参数，猜参数比多按一次回车更糟。面板的「操作」立即执行、「命令」写入语法，两种行为各自可预期。插入是非破坏性的：可能正打到一半，丢掉那句话是用户没要求的损失。 |
| **两侧栏的收起按钮长在被收起的栏上** | 收起后留一条 9px 的窄条放展开按钮：只留快捷键的话，不知道快捷键的人就进了死胡同。折叠状态持久化，`sendOnEnter` 与折叠都区分「键不存在」和「存了 false」。 |
| **高亮判定放在 `lib`，不放在 store 或 feature** | session store 要给每条消息打 `highlight`，设置侧要维护规则表；放在任何一侧都会让另一侧跨层引用——而 session store 引用一个 feature，等那个 feature 想要 buffer 时就成环了。 |
| **通知在 `applyMessage` 里发出，不在事件桥里** | 判定所需的全部信息都已经在那个函数里：忽略过滤、回放去重、buffer 是否在前台。在别处再写一份相同规则，就是多一份会写错的规则。 |
| **`mentions` 从 session store 移到 `lib/highlight`** | 昵称提及与关键词高亮是同一个问题的两半，放在一起才能共用边界判定；迁移后原测试随实现一起搬，避免两份实现各自演化。 |
| **关键词边界只认 ASCII 词字符** | IRC 是 ASCII 协议、昵称也不含其它字符；而 CJK 没有空格，若把汉字算作词字符，中文关键词在句中反而匹配不到——恰好与预期相反。 |
| **规则以「折叠后的模式」为身份** | 同一个词添加两次应当更新一条规则，而不是叠两条：`/highlight rust` 打两遍的意思就是一条。因此模型里没有单独的 id 字段。 |
| **高亮提醒是有限栈、可点可关** | 侧栏的未读徽标才是持久记录，所以横幅只显示最近几条、关掉不丢信息。桌面通知、托盘、声音需要三平台各自的权限模型，按既定决策留到 M8。 |
| **窗口标题走 Tauri API，`core:window:default` 不够** | 该默认权限集只含只读命令，`document.title` 也不会同步到 OS 窗口标题，因此必须显式加 `core:window:allow-set-title`。标题报的是「有内容的会话数」而不是消息数：会随每行增长的计数器不再是一个信号。 |
